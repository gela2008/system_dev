### 2.3 各画面の設計
| 画面名 | 表示するデータ | ユーザーが行う操作 | エラー時の挙動 |
|---|---|---|---|
| ログイン画面 | ユーザー名入力欄、パスワード入力欄、ログインボタン | ユーザー名とパスワードを入力し、ログインする | ユーザー名またはパスワードが一致しない場合、エラーメッセージを表示する |
| ホーム画面 | ログイン成功メッセージ、学籍番号、学年 | カレンダー画面へ移動する、ログアウトする | 未ログイン状態でアクセスした場合、ログイン画面へ移動する |
| カレンダー画面 | 年、月、月間カレンダー、登録されたタスク・スケジュール、お知らせ件数 | 前月・次月へ移動する、日付を選択する、お知らせ画面へ移動する | 未ログイン状態でアクセスした場合、ログイン画面へ移動する |
| タスク一覧画面 | 選択した日付のタスク、スケジュール、タスクの完了状態 | タスクの完了・未完了を変更する、タスク・スケジュールを選択する、追加する、カレンダーへ戻る | 指定された日付のデータがない場合、タスク・スケジュールがない状態で表示する |
| 追加画面 | タスクまたはスケジュールの入力フォーム、学年に対応した科目 | タスク・スケジュールを選択する、内容を入力する、追加する、戻る | 必須項目が未入力の場合、登録処理を行わず入力を促す |
| 詳細画面 | タイトル、種類、科目、日付、時刻、着手予定日、備考 | 一覧へ戻る、編集する、削除する | 指定されたIDのデータが存在しない場合、「データが見つかりません。」と表示する |
| 編集画面 | 登録済みのタスク・スケジュールの内容 | タイトル、時刻、着手予定日、備考を編集する、保存する、戻る | 指定されたIDのデータが存在しない場合、「データが見つかりません。」と表示する |
| お知らせ画面 | 今日着手予定のタスク、今日締切のタスク、明日締切のタスク、今日・明日のスケジュール | お知らせを確認する、カレンダーへ戻る | 該当するお知らせがない場合、「現在、お知らせはありません。」と表示する |

## 3. DB設計
### 3.1 エンティティ
| エンティティ | 内容 |
|---|---|
| ユーザー | システムを利用するユーザーの情報 |
| 科目 | 学年・学期ごとの科目情報 |
| Todo | ユーザーが登録するタスクおよびスケジュール |

### 3.2 テーブルとカラム
| テーブル | 主なカラム |
|---|---|
| ユーザー（user） | `student_id`（学籍番号）、`name`（氏名）、`grade`（学年）、`username`（ログインユーザー名）、`password`（パスワード） |
| 科目（subject） | `grade`（学年）、`term`（学期）、`subject`（科目名） |
| Todo（todo） | `id`（登録ID）、`student_id`（学籍番号）、`title`（タイトル）、`subject`（科目名）、`date`（日付）、`start_date`（着手予定日）、`time`（時刻）、`note`（備考）、`completed`（完了状態）、`end_time`（終了時刻） |

## 4. システム構成
### 4.1 構成要素

| 構成要素 | 使用技術 | 役割 |
|---|---|---|
| クライアント | Webブラウザ | ユーザーがシステムを操作する |
| Webサーバ | Apache（XAMPP） | HTTP通信を受け付け、PHPを実行する |
| アプリケーション | PHP | 認証、データの登録・取得・更新・削除を行う |
| データベース | SQLite（`data\test.db`） | ユーザー(user)、科目(subject)、Todo(todo)情報を保存する |

### 4.2 通信構成
- ブラウザ ⇄ Apache/PHP：HTTP
- PHP ⇄ SQLite：PDOによるデータベース接続
- PHPからブラウザへ：HTMLを返却
